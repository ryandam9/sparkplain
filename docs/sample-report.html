Critical

Executors exceeded their 12 GB memory limit 6 times

YARN killed 6 executor containers between 02:17 and 02:33. No Java OutOfMemoryError appears, so the 10 GB heap did not fill. The container as a whole went over, which in PySpark usually means the Python worker processes used more than the 2 GB overhead allowance.

containers/application_1727312400000_0187/container_1727312400000_0187_01_000023/stderr.gz:4127 “Container killed by YARN for exceeding physical memory limits. 12.1 GB of 12 GB physical memory used.”

Raise spark.executor.memoryOverhead to 4g, or lower spark.executor.cores to 2 so fewer Python workers share each container.

Critical

Stage 14 aborted after task 112 failed 4 times

Each attempt of task 112 ran on an executor that was then killed for memory. Spark allows 4 attempts per task by default, so the job stopped at 02:34:58. One task failing repeatedly often points to one oversized partition.
